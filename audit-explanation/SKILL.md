# Audit explanation

以当前问题、用户限制、原始材料和实际正文为依据，不以出现了某个标题、句数或“深入浅出”等自评词为通过条件。可以单独审核现有文本；没有规划文件也能做，不强迫先补全流程产物。

输入：待查正文、当前问题／限制、可用来源与真实反馈；必要时读取原始材料而不只看已简化版本。输出：有据缺陷记录及最小修复，或用户只要的修订正文。材料不全时明确审查范围，未核实不能记为已通过。

## 检查什么

1. **选材**：正文每块是否回答当前问题、提供必要前提或阻止结论误用？是否把资料目录当成重点？关键问题有没有漏掉？
2. **入口**：每块新增实质内容是否有具体对象和关系／区别，能对应随后的定义、公式、操作或证据？是否只有好处口号或新术语循环？连续推导无需重复入口。
3. **正式展开**：首次出现的关键符号和范围是否清楚？关键等式理由、推导桥梁和实现分支是否齐全？入口与展开是否冲突？先前提过但用户未确认的前提是否被当成已掌握？
4. **证据**：事实与给定材料是否一致？是否把局部结果扩大为普遍、相关当因果、示意当实测、猜测当事实？缺来源的结论能否保留为未知或有条件判断？

## 缺陷记录

每个缺陷记录 **位置、违反的具体要求、文本依据、影响、严重度、最小修复**。引用短句或等式；漏项可指明缺失发生在哪两个相邻步骤之间，并引用两端文本。不能只写“抽象”“不够深入”而无可核查依据，也不要编造未出现的原文。

- **blocker**：事实／数学错误、入口与公式矛盾、无依据的关键结论或关键条件缺失，使答案错误或操作失效。
- **major**：必要关系、定义或步骤缺失；选材错位；关键新内容没有可进入的具体关系，妨碍当前问题的理解或复现。
- **minor**：不改变正确性或必要内容的冗余、措辞和排版问题。

严重度由实际影响判断，事实／数学错误与必要解释缺口优先于文风。某个样式问题修好不代表主要失败已解决。只有轻微冗余时可以直接删改，不扩成大修。

## 按缺陷修复

| 缺陷 | 最小动作 |
| --- | --- |
| 重点错 | 回 [plan-explanation](../plan-explanation/SKILL.md) 重新检查问题与选材，不只是缩短 |
| 入口抽象或循环定义 | 回 [write-explanation](../write-explanation/SKILL.md)，改写具体对象和关系 |
| 关键推导／实现跳步 | 在断点补定义、等式理由、操作或必要分支 |
| 前提缺失或错误 | 补正前提，同时复核所有依赖它的结论和操作 |
| 证据缺失 | 标明未知或缩小结论；在任务允许时核实来源，禁止编造证据 |
| 重复铺垫 | 删掉不承载新事实、关系、证据或衔接的句子 |

默认一轮检查 → 定点修复 → 对修复及受影响下游复核一轮。复核仍有实质问题时标明未解决之处，不以无限润色掩盖缺证据。明确可修的正确性问题必须修好；无法核实的地方保留未知，不能输出已知错误再声称通过。

用户要审核时输出按严重度排列的有据缺陷和最小修订；用户只要解释或局部改句时直接交付修订正文，默认不展示检查表、过程记录或隐含思考。不要通过格式检查宣布用户已理解；只有真实反馈能说明其理解状态，不默认每段强迫考试。

若同时给缺陷说明和完整修订段落，说明中保留原文证据、影响和修复动作，把完整替换句集中放在修订段落；不要先逐条贴出完整替换句，再把同样句子复制一遍。

## 可选机械检查

仅在已有结构化记录或批量交接时读 [数据约定](../explain-to-human/references/contracts.md)，运行 `python3 scripts/lint_explanation.py record.json`。可加 `--strict` 让已登记的未解决 blocker／major 导致非零退出；脚本不会自行发现全部语义缺陷。

脚本只检查结构、必填项、ID、依赖顺序、**已登记**符号／来源／入口对应和明显完全重复。它不验证公式真假、引用是否支持结论，也不推断未登记的符号或真实可理解性。机械通过必须表述为“登记与结构通过”，不是“讲解通过”。语义判断仍需上述文本证据。样例在 [成对示例](../explain-to-human/references/examples.md)；统一入口见 [explain-to-human](../explain-to-human/SKILL.md)。

维护套装时可运行 [脚本行为测试](tests/test_lint_explanation.py)，独立模型对照任务见 [新测试题](tests/behavior_cases.json)。它们是维护资源，日常讲解不加载测试题，也不以范例答案作为测试提示。
