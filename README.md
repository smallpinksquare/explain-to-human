# Explain to Human

把 AI 整理好的材料，讲成一条人能够跟随的理解路径。

我在使用 AI 做调研时，反复遇到一个问题：它交付了一个内容充实的压缩包，里面有分析、有比较，也有许多值得继续研究的线索。单独看，每份文件都有价值。可当我试着读完它们，却很难说清自己究竟理解了什么。

这一大堆文件里，每一项都很重要，但是并没有**主次**，我还得自己判断先看什么、哪些内容彼此相关、一个结论是怎样推出来的。追问之后，AI 又补出更多解释和文件。材料越来越多，更没可能看完。

而且 AI 给出的逻辑本身不一定通顺，何况 AI 的文字通常存在很多问题，这进一步提高了阅读的困难度。

在人类查资料时，通常的思维路径是：先会凭直觉抓住一个有价值的关系，再顺着它找证据、补细节，逐渐形成认识。然而 AI 把资料一次性交到人类手里，所有信息都是平等的，这条逐步理解的思维路径便没有办法被构建起来。尽管有完整结果，人类却很难理解。

**资料交付完成了，理解却还没有建立。** Explain to Human 从这个困境出发，把选材、讲解和检查写成一套可复用的 skills，让 AI 在提出新内容时，同时说明人该怎样进入、推导和使用它。

## 信息为什么难以吸收

在这些对话里，AI 容易按“还有什么值得覆盖”组织输出：背景之后是概念，概念之后是分类，再补优点、局限和应用。相关内容被铺开了，但它们在当前问题中各自起什么作用，读者仍需要自己判断。

这体现了人与 AI 的截然不同的吸收信息的方式：

人：富有直觉性，需要重点+推导链条，再逐步补充信息形成有主干的网络；多个事件的网络有所交集，形成这方面的认知体系
 ai：所有信息没有重点，或者说全是重点，全部接受，全部一次理解

人类需要的理解顺序可以细化为：先看见一个具体关系，知道它回答什么问题，再沿着推导把这个认识变得精确。新的细节接到已有主干上，不同问题的联系也逐渐形成。比如读一个新方法，我首先需要知道它对什么对象做了什么、为什么这一步有用；理解这些之后，分类、变体和比较才有地方接上去。

这套技能据此区分两种材料的用途：

| 材料给谁用 | 需要保留什么 | 怎样组织 |
| --- | --- | --- |
| 供 AI 继续检索、比较和核查的研究档案 | 细节、来源、证据、分支、尚未解决的问题 | 便于查找、追溯和继续处理 |
| 供人理解当前问题的讲解 | 当前主线、必要前提、关键推导、影响结论的条件 | 从具体关系进入，按理解所需的顺序展开 |

同一份完整档案可以支持多次不同的讲解。读者追问某个判断时，讲解仍应能回到档案中的原始证据。这样，细节有地方保存，眼前的回答也有明确主线。

### 为什么需要一个skill来解决这个问题

只在prompt中要求 AI 列重点，可能得到一份更短、却依然选错重点的清单。只要求它写得自然，可能消除了生硬措辞，却仍然没有说清对象之间的关系。只要求少写一点，还可能删掉真正需要的定义和推导。

例如，“通过多维信息协同增强判别能力”确实把句子简化了，但没有告诉读者发生了什么；“分别计算这个点与各个簇的平均相似度，再比较它更接近哪一簇”才给出了可以继续检查的操作。如果随后要写公式，就还需要定义相似度、说明如何取平均，以及怎样作出判断。

**需要压缩的是无效铺垫，需要补全的是理解所依赖的关系和步骤。**

## 具体如何完成

对 AI 的约束要落在每一块新增的实质内容上。报告开头有摘要，并不能保证后面引入的新方法也讲得清楚；下一轮对话提出了新关系，也需要给读者一个进入它的起点。

1. **先确定这块内容回答什么问题。** 根据读者当前的问题选择材料，保留直接答案、理解答案必需的前提，以及会改变结论的条件。讲解顺序按这些内容的依赖关系安排。
2. **用短而具体的直觉给出入口。** 通常用一至三句说明对象、动作或区别，让读者知道什么影响什么。像“更高效”“更鲁棒”这样的评价，需要进一步落到实际机制上。
3. **展开必要的定义、推导或实现。** 符号先定义，关键等式给出理由，操作说明输入、顺序、输出和必要分支。需要长推导的地方就完整写出，让读者能沿步骤检查。
4. **核对讲解是否接回了原问题。** 直觉应当与公式或操作对应，结论应当落在证据支持的范围内。发现断点就修复具体位置，并复核受影响的后续内容。

一块内容可以跨越几个自然段，一段连续推导也可以共用一个入口。已有概念之间新建立的关系，同样需要解释；读者明确说已经懂了的部分可以直接承接。简单事实直接回答，只改一句就处理那一句。

## 一个讲解例子

下面用一个只需一元求导的例子，展示短直觉与必要推导怎样连接。它是教学示例。

问题：估计一个数时，为什么增加平方惩罚会把结果拉向零？

一种容易留下理解断点的回答是：

> 正则化通过平衡拟合与复杂度增强模型的鲁棒性。易得最优解为 a/(1+λ)。

这里没有说明惩罚加在什么上、公式从哪里来，“鲁棒性”也没有得到论证。按这套技能的要求，可以这样展开：

我们希望估计值接近观测值，同时又不希望估计值的绝对值太大。这两个要求会发生拉扯：前者让它靠近观测，而后者却把它拉向零。

设观测值为实数 $a$，待求的估计值为实数 $x$，惩罚强度为 $\lambda\geq 0$。把两个要求写成要最小化的函数：

$$
f(x)=(x-a)^2+\lambda x^2.
$$

第一项在 $x$ 偏离 $a$ 时增大；当 $\lambda>0$ 时，第二项在 $x$ 远离零时增大。对两个平方项分别求导，得到

$$
f'(x)=2(x-a)+2\lambda x=2\bigl((1+\lambda)x-a\bigr).
$$

在整个实数范围内求极小值，候选点须满足 $f'(x)=0$，所以 $(1+\lambda)x=a$。由于 $1+\lambda>0$，可以相除得到

$$
x^*=\frac{a}{1+\lambda}.
$$

二阶导数 $f''(x)=2(1+\lambda)>0$，函数处处向上弯曲，因此这个点是唯一的全局最小点。没有惩罚时，$\lambda=0$，结果就是 $a$；惩罚增大时，分母增大，非零结果的绝对值变小，符号保持不变。例如 $a=6$、$\lambda=2$ 时，结果是 $2$；若 $a=0$，结果始终为零。

开头的“两个要求”对应两个平方项，“拉向零”对应最后的缩放关系。讲解保留了定义、求导、求解和最小值判定，读者可以逐步核对。

更多例子见 [成对示例](explain-to-human/references/examples.md)，涵盖实现步骤、论文机制、方案比较和单句修改。

## 四个技能

一段讲解可能在不同位置出问题：内容选错了、关系没说清，或推导漏了一步。套装把这些工作分开，方便在出错的位置修复。

| Skill | 负责什么 |
| --- | --- |
| [explain-to-human](explain-to-human/SKILL.md) | 统一入口：识别当前需要，按需组织选材、写作与检查 |
| [plan-explanation](plan-explanation/SKILL.md) | 确定讲什么、先讲什么，保留必要前提，形成简短内容规格 |
| [write-explanation](write-explanation/SKILL.md) | 给新内容具体入口，写清必要的数学或实现步骤，删除空话与重复 |
| [audit-explanation](audit-explanation/SKILL.md) | 对照原材料检查重点、关系、步骤和证据，定位缺陷并作最小修复 |

一般从 `explain-to-human` 开始，也可以单独调用某个子技能。一次回答中就可以完成规划、写作和检查；局部修改只走需要的部分。

技能文件面向 AI，详细规定选择与检查的方法；给读者的回答则根据当前问题自然展开。批量处理需要结构化交接时，可使用附带的 [数据约定](explain-to-human/references/contracts.md) 和检查脚本。

## 安装与使用

### 安装到 Codex

下载或克隆本仓库后，将四个技能目录一起安装，并保持它们同级。当前 Codex 官方文档列出的用户级目录是 `~/.agents/skills/`，项目级目录是项目中的 `.agents/skills/`。以下采用用户级安装。参见 [官方技能文档](https://learn.chatgpt.com/docs/build-skills)。

在下载后的仓库根目录执行（macOS / Linux）：

```sh
mkdir -p "$HOME/.agents/skills"
cp -R explain-to-human plan-explanation write-explanation audit-explanation \
  "$HOME/.agents/skills/"
```

如果已安装过同名技能，更新前先备份并移走旧目录，避免混用新旧文件。安装后，四个 `SKILL.md` 应分别位于：

```text
~/.agents/skills/
├── explain-to-human/SKILL.md
├── plan-explanation/SKILL.md
├── write-explanation/SKILL.md
└── audit-explanation/SKILL.md
```

每个目录里的 `references/`、`agents/`、`scripts/` 等配套内容也应一并保留。Codex 会自动发现技能变化；如果尚未出现，重启 Codex 后再检查。安装发现机制见 [官方说明](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills)。

### 从一次真实的理解困难开始

在支持 `$` 技能调用的 Codex 界面中，可以直接输入：

```text
$explain-to-human 根据这份调研解释这个方法怎样工作。
我知道它要解决什么问题，但不理解中间这一步为什么成立。
请保留必要公式和推导。
```

只需要规划时：

```text
$plan-explanation 这些材料里，我现在只想理解方法 A 和方法 B 的区别。
请确定比较标准和必要前提，给出简短的讲解顺序。
```

已经有讲解稿时：

```text
$audit-explanation 检查下面这段讲解。
重点看有没有未定义的符号、跳过的推导，以及超出原材料的结论，
并在有问题的位置作最小修订。
```

已有内容规格时，可用 `$write-explanation` 按规格写正文。局部问题也可以直接告诉入口技能：“只改这句，让对象和关系更清楚”。更多调用示例见 [调用与安装边界](explain-to-human/references/usage.md)。

## 怎样继续改进

使用中最有用的反馈，是指出具体断点：重点选错了、某个符号没有定义，或两步之间缺少理由。套装据此重新选材、补定义或补推导，并检查后续是否重复同类问题。用户明确表示掌握了某个内容后，后续讲解可以从那里继续。

需要更稳定地执行这些要求时，可以在外部工作流中明确安排规划、写作、检查三个阶段，让它们读取同一份原始材料和任务要求；也可以在阅读界面上先展示主干，按需展开推导与来源。这些是可继续建设的方向。

本仓库目前提供四个技能、参考资料和可选的结构检查脚本。技能仍可能被漏用，模型也可能选错重点或作出错误判断；安装不会保证每轮自动执行。脚本能检查已登记的结构和关联，公式是否正确、读者是否理解，仍需内容核查与真实反馈。设计说明见 [设计边界与外围流程](explain-to-human/references/workflow.md)。
