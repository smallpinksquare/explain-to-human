# Write explanation

从读者当前要解决的问题出发写正文。有计划就依其内容约束，没有计划则先快速检验选材；大幅偏题时交给 [plan-explanation](../plan-explanation/SKILL.md)。只改一句时在该句内完成，不附赠教程或审查记录。

输入：当前问题与限制、内容规格（若有）、可用证据及真实理解反馈。输出：自然正文或所要求的局部改句。若关键事实或推导无法核实，缩小结论、标明未知或询问必要信息，不靠顺畅措辞补全。

单句改写优先替换妨碍理解的操作名和抽象名词，把真实动作直接写进原句；不要只把术语换成另一个术语。保留原句的对象、量词和条件，原文未确定的操作细节不要自行补成确定实现。

## 给每块新增实质内容一个入口

直觉通常用 **1–3 句**：说明具体对象、发生的动作或关系、结果，以及这个关系怎样回答当前问题。不要机械写出四个标签。静态概念没有动作时，用具体区别说明哪些情况属于它、哪些不属于它。先出现可识别的对象，再引入术语；不用几个未解释的新术语循环定义另一个。

句数是默认，不是上限。新增句应补上一个确实缺的关系或区别；超出只为渲染意义就删。入口之后可分多段推导，不必每段重启直觉；新增独立机制、结论或操作时才需要新的简短入口。后续轮次有新实质内容也遵守这个要求，不能以“前文出现过”为已掌握的证据。

每个新概念或术语都要帮助表达当前问题中的某个关系；没有明确作用就不要额外引入。用户已明确理解的内容直接承接，不重复通用入门介绍。

“更高效”“更鲁棒”“协同赋能”“改善体验”是评价，不能代替机制。用“谁对什么做了什么，哪项量或状态怎样变化”说清关系。类比可帮助进入问题，但要把对应关系落回真实对象；类比不支持的结论不能带入正式展开。

检查入口能否支持一句具体复述：“什么对象，发生了什么变化／有什么区别”。只剩“重要、效果好”、换种说法重复方法名、或很长但无真实对应的比喻，均须重写。这是对文本的检查，不是声称读者已经掌握。

## 完整展开必要细节

- **定义和条件**：符号第一次正式使用时说明含义、类型或维度，以及影响结论的取值范围、假设、边界。不要先用一个未知符号解释另一个。通用算术记号无须逐一教学。
- **数学**：给关键等式／不等式的理由和关键中间步骤，包括换元、求导、消去、可逆性、极值判定等实际用到的桥梁。“显然”“由此可得”不能跨过当前读者尚不具备的那一步。必要长推导不受机械长度或段数限制；“完整”不等于补讲所有无关基础知识。
- **实现**：说明输入、执行顺序、操作、输出以及影响结果的必要分支；包括实际相关的初始化、空输入、零分母、失败或重复执行条件。只给函数名或最终表达式不能替代必须执行的步骤。不要凭空扩展成生产工程清单。
- **证据**：材料所述事实、自己的推导、示意例子、待验证猜测分开表述。保留支持结论的适用条件、比较对象、指标方向、单位和范围；来源未明确单位或统计口径时沿用原始数值，必要推断须说明假设，不擅自添加百分号或默认统计定义。无数据时不能补成“实验证明”。

核对入口与正式展开的一一对应：入口中的每个机制判断都应能指向一个定义、等式、操作或给定证据；正式展开中新加的关键关系也须有入口可进入。不是强制每句配一个公式，而是不允许“保留方向”后写出改变方向的操作，或说“保证最优”却仅给启发式步骤。

展开应让读者知道具体得到了什么，以及它解决了开头问题的哪一步。若公式或输出已清楚回答，无须追加总结；只有原问题尚未被明确回答或关键边界仍未交代时，才补一句结果或限制。

## 删掉不承载信息的句子

试删一句：事实、关系、定义、证据和必要衔接均无损，就优先删。删除反复的意义宣言、预告、自我评价、同义复述；默认不在结尾重说一次答案。保留真有作用的过渡、适用条件和关键实现。读起来连贯自然即可，不强制“直觉／公式／实现／检查”等固定标题。

写完按 [audit-explanation](../audit-explanation/SKILL.md) 检查，定点修复主要缺陷。不要宣称读者“现在已经理解”。
